# DevSnip Pro audit — 29 October 2026

## Result and scope

Implemented targeted reliability and dependency security fixes against the existing, substantially modified workspace. Existing browser-support and other user changes were preserved. This is an evidence-based audit pass, not a certification that every feature, operating system, external service, or line of code is defect-free. No working feature or public command was removed.

Reviewed activation entry points, manifests, TypeScript and lint configuration, lazy registration and command dispatch, toolkit execution and output handling, platform boundaries, database secret storage, test infrastructure, browser bundling and VSIX contents. Existing automated suites exercise toolkit engines, webview escaping/CSP, database adapters, scanners, spreadsheets, rewards, snippets and onboarding.

## Confirmed issues fixed

1. **Lazy command availability during imports.** Disposing all placeholders before asynchronous imports completed made other commands in the group unavailable. Placeholders now remain registered until their actual handler replaces them; concurrent requests share a pending load.
2. **Partial registration failures broke retries.** If a loader registered one command and then failed, reinstalling placeholders could collide with that command. Failed groups now roll back tracked registrations before reinstalling placeholders.
3. **Synchronous loader failures retained rejected state.** Loading starts in a promise continuation, so retry state is reset after the pending promise has been assigned.
4. **Command lifecycle retention.** Disposed tracked commands remained in the webview dispatch allow-list; retry attempts accumulated placeholder subscriptions. Disposal now removes registry entries, groups use one lifecycle subscription, and shutdown during loading cleans up late registrations.
5. **Test shim masked registration defects.** It previously overwrote duplicate commands and ignored disposal. It now rejects duplicates and disposes registrations, with idempotent Disposable support.
6. **Python generator tests wrote outside their temporary directory.** Explicit bytecode destinations now keep compilation artifacts in the test directory while retaining syntax validation and cleanup.
7. **Dependency advisories.** Applied compatible lockfile updates using `npm audit fix --ignore-scripts`. Findings fell from 11 (8 high, 2 moderate, 1 low) to 5 high, all from the remaining MSAL dependency chain. Patched transitive packages include follow-redirects, undici, fast-uri, markdown-it, qs and serialize-javascript. No forced major upgrades or new direct dependencies were added.

## Performance and remaining limitations

The command lifecycle fix bounds group-level subscription growth across retries and releases disposed registry entries. Existing lazy loading remains in place. The desktop panel lifecycle test passed, with retained heap readings of 68.3 → 68.5 → 68.7 → 68.9 → 69.0 MB across five cycles; this is a bounded regression check, not proof of zero leaks. No startup/CPU benchmark was performed and no measured activation speedup is claimed. VSCE warns about 3,200 packaged files, including 2,133 JavaScript files; desktop bundling remains an optimization opportunity requiring separate driver/asset compatibility testing.

The remaining high findings are `@azure/msal-node`, `@azure/identity`, `tedious`, a nested `@vscode/vsce`, and `ovsx`. These represent one underlying advisory, GHSA-xcx6-jx8p-x3h5. MSAL versions before 7.1.0 are affected; Azure Identity 4.14.0 currently declares MSAL `^6.0.0`. An override across major versions has not been applied because Azure/database authentication compatibility has not been demonstrated. Upstream advisory: https://github.com/advisories/GHSA-xcx6-jx8p-x3h5 . Database authentication code is part of the production dependency graph, so this cannot be dismissed as solely a development-tool warning.

Live PostgreSQL, CockroachDB, MySQL, MariaDB, SQL Server, Oracle, ClickHouse, MongoDB and Redis tests require configured servers. Windows/Linux, the minimum VS Code 1.93 host, marketplace publication, external provider credentials and every manual UI interaction were not verified. This build should not be described as fully production-certified until the outstanding security and environment checks are resolved.
